User flows

How each role moves through the centralized workspace platform: the platform map, the three roles, and a step chain for every job to be done — validation failures, rejected-record retry, unreachable sources, and deactivation included. The working prototype lives separately.

1 · Platform map

One shell, seven screens. Every module — IMS, Sales Operation, Billing API, Support Desk, Payroll Export, CRM Mirror — renders through the same module screens.

Overview

#/overview

Shared metrics across all modules, per-module cards, attention list, activity feed.

Data pipeline

#/pipeline

Per-module validation rules, staged runs, rejected-records store with retry.

Module registry

#/registry

Manifest wizard, adapters, activate / deactivate without a deploy.

Module dashboard

#/module/:id

KPIs, trend, group chart, domain panel — same renderer for every module.

Records

#/module/:id/records

Schema table, search and filters, add-record form, CSV export.

Backups & restore

#/backups

Schedule, retention, snapshot history, confirmation-gated restore.

Sign-in & roles

account menu

Role switcher standing in for authentication; permissions follow the role.

Rejected store

inside #/pipeline

Failed records kept with the failing rule named — never discarded silently.

Department Employee

Reads every dashboard; enters records in native modules only. External modules stay view-only.

Organization Admin

Configures pipeline rules, registers and activates modules, runs and restores backups.

Client Super Admin

Read-only oversight across all modules, pipelines, and backup history.

2 · User flows

Step chains for every job to be done, covering all three roles and the edge paths: validation failures, rejected-record retry, unreachable sources, and deactivation.

Sign in & switch roleAll roles#/overview
  1. 01Open the workspaceLands on Overview
  2. →
  3. 02Account menu (top right)
  4. →
  5. 03Pick a roleEmployee / Org Admin / Super Admin
  6. →
  7. 04Permissions updateAdmin-only controls appear or disable
  8. →
  9. 05Work in any tab

Rule: the role switcher stands in for real authentication; registry, rule, and backup actions are Organization Admin only.

Enter data in a native moduleEmployeeOrg Admin#/module/ims → records
  1. 01Open a native moduleIMS or Sales Operation
  2. →
  3. 02Records tab → Add record
  4. →
  5. 03Fill the formValidates on blur
  6. →
  7. PassRecord queues for the pipeline and lands in the dashboard after the run.
    FailError beside the field with the cause and remedy; nothing is queued.

Rule: native-module users may input data; external modules (Billing API, Support Desk, Payroll Export, CRM Mirror) show a read-only notice instead of the form.

Clean & validate inbound dataOrg Admin#/pipeline
  1. 01Open Data pipeline
  2. →
  3. 02Select the module
  4. →
  5. 03Edit validation rulesRequired, format, duplicates, allowed values
  6. →
  7. 04Run the pipelineIntake → clean → validate → load → report
  8. →
  9. 05Read run statsPassed / rejected counts
  10. →
  11. RejectedRecord kept in the store with the failing rule named.
    NextFix the source → Retry, or Discard with a log entry.

Rule: every record — native input, bulk upload, external sync — passes through the pipeline first; failures are never dropped silently.

Register & activate a moduleOrg Admin#/registry
  1. 01Open Module registry
  2. →
  3. 02Register · step 1Identity, routes, permissions
  4. →
  5. 03Register · step 2Adapter File / DB / API / Webhook, connection, field mapping, sync mode
  6. →
  7. 04Register · step 3Pipeline rules, dashboard config
  8. →
  9. 05Submit as inactive
  10. →
  11. 06ActivateSidebar entry, routing, permissions — no code deploy

Branch: Deactivate hides the entry and stops sync while keeping its data. Rule: only Organization Admin sees the Register and Activate controls.

Read the analyticsAll roles#/overview → #/module/:id
  1. 01OverviewShared metrics across modules
  2. →
  3. 02Pick a module card
  4. →
  5. 03Module dashboardKPIs, trend, group chart, domain panel
  6. →
  7. 04All recordsFilter, page, export CSV
  8. →
  9. 05Back to Overview

Rule: dashboards are served from cached per-module analytics; native and external modules render through the same component.

External sync & stale sourceOrg Admin configuresAll roles read#/module/crm-mirror
  1. 01Adapter syncsReal-time where supported, batch otherwise
  2. →
  3. 02Source reachable?
  4. →
  5. YesFresh rows load with an updated last-synced timestamp.
    NoLast synced snapshot keeps serving behind a stale-source banner.
  6. →
  7. 03Read-only viewInput attempts show a view-only notice

Rule: the workspace never writes back to an external source system; availability beats strict consistency when a source is unreachable.

Backup & restoreOrg Admin#/backups
  1. 01Open Backups
  2. →
  3. 02Set schedule & retention
  4. →
  5. 03Snapshot takenScheduled or Run now
  6. →
  7. 04Pick from history
  8. →
  9. 05Restore → confirmDestructive action, second step required
  10. →
  11. 06RestoredLog-only in the prototype

Rule: only Organization Admin may configure the schedule, take snapshots, or restore; every other role sees history read-only.
